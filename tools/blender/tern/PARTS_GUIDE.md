# ST-7 "Tern" — guide for part modules

The Tern is the player's starter ship: a light expedition craft, ~15 m long, 13.7 m span, exterior only.
Target look: **AAA hero-asset hard-surface** (Star Citizen class): believable aerospace engineering,
crisp bevelled edges, layered construction, rich but *organised* mechanical detail, PBR materials with wear.
Everything is generated by headless Blender 5.2 Python scripts (bmesh), rendered in Cycles on an RTX 3060.

## Files
- `tools/blender/tern/kit.py` — geometry toolkit (read it first: lathe, cylinder, ring, torus, box, prism, loft,
  tube, fillet_path, bevel_all, to_obj, join, instance, mirrored_copy, place, frame, T/R/S matrices, 2D outlines,
  mod_bevel / mod_solidify / mod_subsurf / apply_mods, Panelizer).
- `tools/blender/tern/mats.py` — material library: `mats.get(name)`; `mats.names()` lists them. Custom ones via
  `mats.surface(name, color, rough, metallic, coat, wear, grime, ...)`, `mats.emissive(name, color, strength)`,
  `mats.heat_metal(name, axis, start, length)`. All are object-space procedural: **no UVs needed**.
- `tools/blender/tern/studio.py` + `part_preview.py` — preview renders.
- `tools/blender/tern/design.py` — ship master dimensions (read-only reference).
- **Your module**: `tools/blender/tern/parts/<name>.py`. You own only that file (plus your preview output folder
  `build/tern/parts/<name>/`). Do **not** edit kit.py / mats.py / studio.py / design.py or other parts; if you
  need something they lack, implement it locally in your module and mention it in your final report.
  Do not run git commands that change anything (no add/commit/push/checkout/stash).

## Running
```
"C:\Program Files\Blender Foundation\Blender 5.2\blender.exe" -b --factory-startup -P tools/blender/tern/part_preview.py -- <name> --views=front34,rear34,side,top --res=960x540 --samples=64
```
Output: `build/tern/parts/<name>/<view>.png` and `sheet.png` (contact sheet). Options: `--func=demo_xyz`
(another demo function), `--views=` any of front34, rear34, side, top, front, rear, low34, bottom34, left34,
rearleft34, `--cols=`, `--res=WxH`, `--samples=`, `--clay` (grey override for form checks), `--margin=`.
`demo()` must build the part(s) at the origin and may return the list of objects to frame.
The preview's `front34` etc. assume ship axes (+Y nose). A render takes ~10-40 s. Other agents share the GPU,
so keep previews at 960x540 / 64 samples and render close-ups only when needed (a `demo_*` that returns a small
hidden box frames a detail; see `parts/_selftest.py::demo_zoom`).
**Always open your PNGs with the Read tool and judge them critically; iterate on what you see.** Typical
defects to hunt: flipped normals (black faces), z-fighting, floating/intersecting parts, faceted cylinders,
razor-sharp unbevelled edges, toy-like proportions, noise-like random detail, flat boring large faces.

## Conventions
- Units metres. A part is built in its own local space; unless told otherwise **+Z points out of the hull
  surface / along the part's main axis, the mounting plane is z = 0**, origin on the mount centre.
- Each public `build_*()` returns **one joined mesh object** (several material slots are fine) with identity
  transform, linked to the collection passed as `col` (may be None = scene collection). Build sub-meshes with
  `kit.to_obj(...)` and merge with `kit.join([...], name)`. Apply modifiers (`kit.apply_mods`) before joining.
- No booleans unless unavoidable; overlap/intersect solids instead (the Cycles Bevel shader in the materials
  softens intersections). No subdivision-surface blobs: this is machined hardware.
- **Bevel everything**: 1-3 mm on small parts, 4-10 mm on big castings (`kit.box(bevel=)`, `kit.cylinder(chamfer=)`,
  `kit.mod_bevel`). Cylinders >= 32 segments when larger than 10 cm, >= 16 when small. Smooth shading with
  sharp edges by angle (to_obj does it).
- Normals must face outward (`to_obj(recalc=True)` fixes closed shells; for open shells build the winding right).
- Materials (see `mats._LIB`): `metal_dark` (gunmetal, the default for mechanisms), `metal_steel`, `metal_alu`,
  `metal_chrome` (piston rods), `metal_brass` (fittings), `metal_heat` (heat-tinted titanium), `metal_soot`,
  `rubber`, `plastic_black`, `ceramic`, `inner_dark` (deep recess filler), `paint_white` (hull colour),
  `paint_dark` (graphite), `paint_grey`, `paint_accent` (signal orange — use sparingly, <10 % of a part),
  `paint_hazard` (yellow), `glass_dark`, `lens_clear`, emissives `emit_engine`, `emit_engine_hot`, `emit_cyan`,
  `emit_white`, `emit_red`, `emit_green`, `emit_amber`.
- Design language: functional near-future aerospace. Every element should look like it does a job (actuator,
  hinge, duct, clamp, sensor, fastener, cable run). Detail hierarchy: 1-2 big readable forms, a layer of
  medium forms (collars, ribs, brackets, panels), then small detail (bolts, pipes, vents) grouped in clusters
  with calm surfaces between. Chamfered / octagonal shapes rather than plain boxes. No text, no logos.
- Triangle budgets are given per part; stay inside them (print `len(ob.data.polygons)` in your demo).
- Code: Python, English comments, parameters as keyword arguments with defaults, no global side effects on
  import, deterministic (seeded `random.Random(n)` if you need variation).
