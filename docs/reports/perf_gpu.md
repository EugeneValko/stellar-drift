# Оптимизация производительности на реальном GPU (ветка `perf-gpu`)

Машина: RTX 3060 (драйвер 32.0.16.1088), Ryzen 7 5700X, Windows 11, 1920x1080 fullscreen, vsync off, MSAA 2x
(как в `project.godot`).
> Поправка 2026-11-02: `msaa_3d=2` в `project.godot` — это **MSAA 4x**, не 2x; все замеры этого отчёта сняты с 4x
> (см. `docs/reports/perf_wave5.md`, теперь по умолчанию 2x). Цель навигатора: ≥ 80 FPS на 3060 в худших видах (≈ 60 FPS на RTX 2060-классе),
без заметной потери красоты. Зона изменений: облака, атмосфера, океан, флора (+ бенч-скрипты).

## 1. Инструменты замера
- `tools/dev/gpu_bench.gd`: SceneTree-скрипт, грузит сцену (Capture применяет `--cam`), ждёт `--warm` кадров,
  затем `--frames` кадров меряет GPU-время вьюпорта (`viewport_get_measured_render_time_gpu`), CPU-время,
  время кадра, draw calls, примитивы; `--snap=` сохраняет кадр.
- `tools/dev/gpu_bench.ps1 -Views "main:terra_low,atmo_test:ocean_glint" [-SnapDir d] [-Extra "--cu_x=1"]`.
- `tools/dev/gpu_ab.ps1 -Views ... -Variants "a|--flag;b|" -OutDir d`: матрица A/B со снимками.
- Флора строится асинхронно: для `scatter_test` нужен `-Warm 900`, иначе «до/после» сравнивают
  недостроенные патчи (на 300 кадрах результат зависит от FPS).

## 3. Что изменено

### Облака (`shaders/clouds.gdshader`, `clouds_common.gdshaderinc`, `cloud_layer.gd`)
До: облака стоили 4.0–5.2 мс в видах Terra (main, quality 1) и ~9.3 мс в `atmo_test` (quality 2).
1. **Разделение марша на квад 2×2 (`cloud_quad_share`, по умолчанию вкл.)**: каждый пиксель квада идёт вдвое
   меньшим числом (вдвое более длинных) ячеек и берёт в каждой свою четверть (0, ¼, ½, ¾; назначение четвертей
   случайно поворачивается на каждый квад, позиция внутри четверти — случайная на пиксель). После цикла пиксель
   смешивает свой результат (½) с соседями по X и Y (¼ + ¼) через `dFdxFine/dFdyFine` (цвет, пропускание,
   глубина для перспективы). На перепадах глубины (силуэт горы перед облаком) смешивание отключается.
   Итог: ~2× дешевле марш, без «блоков 2×2» и без регулярного узора; зерно того же масштаба, что и было.
   Эффект: −1.5…−4 мс в облачных видах.
2. Перистые облака берут уже посчитанную небесную подсветку кучевых (−0.1…−0.3 мс, визуально без изменений).
3. `quality 0`: дальше 30 км — билинейная погода и марш к солнцу на шаг короче (`bicubic_distance`, `light_far`).
   На quality 1/2 выключено (с орбиты облака становились чуть площе).
4. Погода: функции по UV (`cloud_weather_bicubic_uv/_fast_uv`), `textureLod` (без производных в цикле).

### Атмосфера (`atmosphere.gdshader`, `atmosphere_transmittance.gdshader`, `atmosphere_common.gdshaderinc`)
- Тот же квадовый приём для обоих полноэкранных проходов (`atmo_quad_share`, по умолчанию вкл.;
  `atmo_quad_steps/jitter/blend`). Результат гладкий, на силуэтах не смешивается. −0.35…−0.5 мс.

### Флора (`src/planets/scatter/planet_scatter.gd`)
- `PlanetScatter.quality` 0/1/2 (по умолчанию **1**), таблица `QUALITY`: множители дальности теней, дальнего
  кольца деревьев, LOD-дистанций и плотности мелкого покрова (трава/цветы/галька, `cell_size < 48`).
  q1 = тени 1.0, дальнее кольцо 0.8 (3000 → 2400 м), LOD 0.85, покров 0.8; q0 = 0.45 / 0.6 / 0.7 / 0.6.
  Отладка: `--scatter_quality=N`, `--scatter_shadow|far|lod|cover=x`. Эффект q1: −0.6…−1.2 мс, визуально
  без изменений (сравнение при равном прогреве). q0: ещё −0.7 мс, но тени деревьев короче.

### Океан
Не трогал: 0.2–0.4 мс в худших видах.

## 4. Куда уходит кадр (замеры «до», вычитанием)

`terra_ground` (16.7 мс): облака 4.9, атмосфера 1.3, океан 0.4, **тени ≈ 3.9** (`--no_shadows` → 12.8),
**рельеф + небо + пост ≈ 7.0** (без теней и трёх слоёв). После оптимизаций облака ≈ 2.0, атмосфера ≈ 0.8.

`hillside_view` (20.8 мс): флора 3.2 (из них **тени флоры ≈ 2.2**), атмосфера 1.0, **рельеф + его тени до 1500 м ≈ 15**.

Чтобы получить ≥ 80 FPS в `terra_ground`/флоре, нужны изменения вне моей зоны:
1. **Тени** (`SolarSystem`, `project.godot`): `directional_shadow/size` 8192 → 4096, 4 → 3 сплита и/или короче
   `shadow_max_distance` у земли. Ожидаемо −1.5…−2.5 мс в `terra_ground`.
2. **Рельеф** (`planet_terrain.gdshader`, LOD): ~7 мс у земли — профилировать шейдер (число октав шума
   в фрагменте, triplanar-выборки), `lod_factor`.
3. **AA**: включены и MSAA 2x, и FXAA (`screen_space_aa=1`) — выбрать одно.
4. **Флора**: тени листвы с alpha-scissor в 4 каскадах — дорогие; варианты: отдельные shadow-only MultiMesh
   с LOD1/оболочкой без scissor, тени деревьев только в 1–2 ближних каскадах.

## 5. Что пробовал и отказался (с замерами)
- Карта грубой занятости погоды для пропуска пустых шагов: у Terra покрытие почти нигде не нулевое — 0 мс.
- Адаптивный шаг с прыжками в пустоте (до 4 ячеек, возврат при попадании): −1.3 мс у земли, но рвёт края
  облаков (тонкие края пропускаются), а сам цикл без прыжков дороже исходного на 0.3–0.6 мс.
- Интерполяция погоды вдоль луча блоками по 4 ячейки: −1…−2 мс, но горизонтальные «ступени» и пропажа
  мелких облаков вдали.
- Погода сэмпла для марша к солнцу (без своих выборок): −0.6…−2.7 мс, но облака с орбиты заметно площе.
- Полное усреднение квада (¼×4): «блоки 2×2» на краях с орбиты; фиксированные четверти — полосы. Итог — см. §3.
- Шаг по конусу (размер пикселя): в наших видах не уменьшает число шагов — 0 мс.

## 6. Что ещё можно сделать
- Облака в половинном разрешении + темпоральное накопление (CompositorEffect / compute) — ещё −1.5…−3 мс,
  и уходит зерно; требует камеры/окружения (вне зоны).
- LUT небесной подсветки (r, μs) вместо 8 шагов на пиксель в облаках — −0.3…−0.6 мс.
- `atmo_test` использует quality 2 (96 шагов облаков) — для игры достаточно quality 1.
