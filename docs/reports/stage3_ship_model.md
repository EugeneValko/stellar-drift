# Этап 3 — модель корабля игрока (SD-7 «Kestrel»)

Скриншоты (1920×1080): `docs/screenshots/s3/ship/` — `ship_hero`, `ship_side`, `ship_rear`, `ship_top`, `ship_landed`.

## Что сделано
| Файл | Назначение |
|---|---|
| `tools/blender/ship.py` | Полностью процедурная модель (bpy/bmesh) → `assets/models/ship.glb` |
| `assets/models/ship.glb` (+ `.import`) | Сгенерированная модель (коммитится) |
| `scenes/ship/ship_visual.tscn`, `src/ship/ship_visual.gd` | `ShipVisual`: инстанс GLB, подмена материалов, анимации, огни, выхлоп |
| `shaders/ship_hull.gdshader` | Корпус (слоты `Hull`, `HullDark`, `Trim` с разными параметрами) |
| `shaders/ship_glass.gdshader`, `ship_emissive.gdshader`, `ship_engine.gdshader`, `ship_plume.gdshader` | Стекло, светящиеся полосы, сопло, факел |
| `shaders/ship_studio_sky.gdshader` | Независимое «студийное» небо только для тестовой сцены (не зависит от неба этапа 1) |
| `assets/materials/ship/*.tres` | Материалы (ShaderMaterial) для 6 слотов |
| `scenes/test/ship_test.tscn`, `src/ship/ship_test.gd` | Look-dev сцена, пресеты съёмки |

Пересборка модели: `blender -b -P tools/blender/ship.py -- assets/models/ship.glb [--blend out.blend]` (~5 с),
затем `godot --headless --import` (важно: `tools/shot.sh` не переимпортирует, если `.godot/` уже есть).

## Дизайн
Оригинальный космоплан-исследователь/истребитель, длина ≈ 20,2 м (нос → срез сопел), размах ≈ 14,8 м,
высота на шасси ≈ 5,3 м (по кили). Не копирует существующие корабли; ключевые элементы силуэта:
- **Несущий фюзеляж** с плоским «лопатообразным» носом и **острой скулой-лезвием (chine blade)** по всей длине —
  она же разделяет двухцветную окраску (светлый верх / графитовое брюхо).
- **Низкий гранёный фонарь** (6 граней поперёк), переходящий в **дорсальный хребет** с радиаторными ламелями.
- **Блок двигателей**: две крупные гондолы со «срезанными» наклонными воздухозаборниками, связанные с фюзеляжем
  палубой (engine deck), + малый центральный маршевый двигатель. Сопла квадратно-скруглённые (суперэллипс),
  с титановым раструбом, цветами побежалости и **светящимся кольцом** по срезу — фирменная «подпись» корабля.
- **Стреловидное крыло (≈ 50°) с опущенными законцовками-килями** (графит) и наклонёнными наружу на 34° стабилизаторами.
- Ливрея (процедурная): тёплый белый корпус, **графитовое «седло»** с шевроном над двигательной палубой,
  двойные оранжевые полосы на гондолах, пинстрайп вдоль борта, антиблик перед фонарём, шевроны на крыле,
  тёмная кромка крыла, номер «07» на килях, жёлто-чёрная разметка вокруг рампы.
- Шасси — три телескопические стойки с опорами-«тарелками», ножничными тяг-звеньями и щитками-створками на стойках;
  **рампа** в брюхе за кабиной (с подсветкой краёв) — вход/выход пилота.

Параметры пропорций — в начале `ship.py` (`NOSE_Y`, `FUSE_*`, `NAC_*`, `WING_*`, `FIN_*`, `GROUND_Z`, `GEAR_*`,
`HATCH_*`, `CANOPY_*`) и профили сечений (`FW/FHT/FHB/FZC/FCH`, `NA/NB`, `CW/CT`, `SPINE_T`, монотонные кубические сплайны).

## Пайплайн модели
Лофт сечений (суперэллипсы + скула) → булевы UNION (крыло, гондолы, палуба, кили, хребет) →
DIFFERENCE (кабина, ниша рампы, ниши шасси; материал срезов = `HullDark`, режим TRANSFER) → Bevel по углу (2,2 см, 2 сегм.)
→ острые рёбра по углу 46° + WeightedNormal (keep sharp) → Smart UV Project → запечка в вершинные цвета:
**R = выпуклость (кромки), G = впадины, B = видимость/AO** (20 лучей BVH, радиус 1,6 м) → экспорт GLB (+Y up, extras).

## Оси и маркеры
- Blender: +X вправо, **+Y вперёд (нос)**, +Z вверх. glTF/Godot: +X вправо, +Y вверх, **нос → −Z** (как у Camera3D).
- Начало координат ≈ центр масс на оси фюзеляжа. **Плоскость касания опор шасси: Y = −2,95** (маркер `GroundPoint`).
- Все маркеры — `Node3D` в `Model`; **локальная −Z маркера = направление, куда он «излучает»**:

| Маркер | Позиция (Godot) | Ориентация |
|---|---|---|
| `EngineExhaust_L/R` | (∓2,8, −0,05, 9,9) | −Z = факел назад (+Z корабля); extras: `radius`, `kind=main` |
| `EngineExhaust_C` | (0, 0,22, 8,95) | то же, `kind=aux` |
| `Thruster_Nose{L,R,Up,Down}`, `Thruster_Tail{L,R,UpL,UpR,DownL,DownR}` | на носу и у кормы гондол | −Z = направление струи RCS (наружу) |
| `NavLight_L` (красный) / `NavLight_R` (зелёный) / `NavLight_Top` (белый строб) | законцовки крыла / антенна | identity |
| `PilotSeat` | (0, 0,36, −3,9) — подушка кресла | identity (вперёд = −Z) |
| `PilotEye` | (0, 1,12, −3,8) | identity |
| `ExitPoint` | (0, −2,95, −3,78) — на земле перед концом рампы | identity |
| `GroundPoint` | (0, −2,95, 0) | identity |
| `CameraChase` | (0, 4,6, 19,0) | как Camera3D: смотрит по −Z на корабль |

Анимируемые части (origin = шарнир, исходная поза = шасси выпущено, рампа и фонарь закрыты), вращение вокруг локальной X:
| Узел | Угол (extras) | Смысл |
|---|---|---|
| `GearFront` | `retract_deg = −90` | складывается назад |
| `GearRearL/R` | `retract_deg = +90` | складываются вперёд |
| `Hatch` | `open_deg = −37,9` | передний край опускается до земли (считается в скрипте) |
| `Canopy` | `open_deg = +32` | передний край поднимается |
glTF extras импортируются в метаданные узла `extras` (проверено), в `ship_visual.gd` есть запасные значения.

## API `ShipVisual` (`class_name ShipVisual`)
```gdscript
set_thrust(v: float)                 # 0..1: свечение сопла (HDR), факелы (длина/яркость), OmniLight у сопел
set_gear(deployed: bool, instant := false)   # tween 2,4 с, носовая стойка опережает; сигнал gear_changed
set_hatch(open: bool, instant := false)      # tween 2,0 с; сигнал hatch_changed
set_canopy(open: bool, instant := false)     # бонус
get_marker(name: String) -> Node3D           # null, если нет
get_markers(prefix: String) -> Array[Node3D] # напр. get_markers("Thruster_")
is_gear_moving() -> bool
# export: gear_time, hatch_time, canopy_time, nav_lights, engine_light_energy, plume_length, start_gear_deployed
```
Материалы дублируются на экземпляр. Отдельным мешам (шасси, рампа, фонарь) передаётся instance-uniform
`part_offset` (их положение покоя в пространстве корабля), чтобы панели/разметка совпадали с корпусом.
При `Capture.active` анимации шейдеров замораживаются, навигационные огни горят постоянно.

## Шейдер корпуса (`ship_hull.gdshader`)
Всё в объектном пространстве корабля, без текстур: трипланарная **нерегулярная раскладка панелей** (смещённые ряды,
случайные разбиения), швы с bump-канавкой и антиалиасингом/затуханием, заклёпки, разброс тона/шероховатости по панелям,
**износ кромок** (вершинный R + шум → металл), **грязь** (AO/впадины + потёки вниз), **копоть** у кормы,
**двухцветная окраска** брюха по нормали, процедурные метки (см. «Дизайн»), 7-сегментный номер,
**цвета побежалости титана** у сопел (`heat_tint`), «шлифованный» металл (`brushed`). Параметры — uniforms в `.tres`.

## Тестовая сцена `scenes/test/ship_test.tscn`
Пресеты: `ship_hero`, `ship_side`, `ship_rear`, `ship_top`, `ship_landed`. Ключевой DirectionalLight (тени) +
холодный контровой (только свет, без диска на небе, пониженный specular), процедурное небо (туманности/звёзды/солнце;
режим 1 — закатная атмосфера для посадки), AgX, glow (порог 3,0 — светятся только эмиссивы), SSAO.
Отладочные аргументы: `--thrust=0..1`, `--hide_ship`, `--nonav`, `--norim`, `--plain_mat=<slot>`,
`--campos=x,y,z --camat=x,y,z [--fov=]`.

## Известные проблемы / что слабее
- Силуэт сбоку всё ещё тонковат и «самолётный»; при желании — поднять `FUSE_TOP`/хребет, добавить подфюзеляжный киль.
- Каркас фонаря — две дуги + рельсы, читается как «дуги безопасности»; стоит добавить переплёт/лобовую раму.
- Створки шасси — щитки на стойках (в выпущенном положении это вертикальные «доски» у стоек); при уборке опоры
  последние ~10° проходят сквозь обшивку (ниша рассчитана под щиток, а не под тарелку опоры).
- Ниша рампы — простая коробка (тёмные стенки + полоса света), без интерьера; кабина — упрощённая (кресло, пульты, экраны).
- Блик контрового света на больших плоскостях при некоторых ракурсах всё ещё заметен (физически корректный «глинт»).
- Сабпиксельные швы панелей гасятся на дальних планах — издалека корпус читается за счёт ливреи, а не панелей.
- `ship.glb` не побайтно детерминирован между прогонами (порядок float), геометрия одинакова.
- В рантайме LOD/коллизия корабля не настроены (для физики нужен отдельный упрощённый коллайдер — следующий шаг этапа 3).
