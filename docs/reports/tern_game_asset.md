# ST-7 «Tern» — игровая (real-time) версия

**Дата:** 2026-11-11 · **Статус:** ассет готов и проверен импортом в Godot 4.7.2; в игру (main scene, `ship_visual.gd`) НЕ подключён.

Запрос: «нужна оптимизированная версия под игры» для hero-модели из `docs/reports/tern_starter_ship.md`
(~1,1 млн треугольников, процедурные материалы Cycles без UV). Результат — три LOD в glTF с запечёнными PBR-картами.

| `tern_lod1.gltf` + `.bin` | 0,04 + 2,0 МБ | LOD1, **36 869** |
| `tern_lod2.gltf` + `.bin` | 0,02 + 0,6 МБ | LOD2, **~9 030** |

Всего папка ~19 МБ. Текстуры общие для всех LOD. WebP качество 90; Godot 4.7.2 импортирует их без ошибок.
У атласов A/B нет emission (на корпусе нет видимых излучателей: посадочные фары в hero-модели закрыты обшивкой).

**Атласы:** A = фюзеляж + щёки (обтекатели пушек) + центральные тела воздухозаборников; B = мотогондола + крыло + киль + законцовка;
C = все уникальные детали. Плотность: A ≈ 286 px/м, B ≈ 329 px/м (≈ 3–3,5 мм на тексель — соответствует виду с ~3 м),
C в среднем ≈ 190 px/м (у мелких деталей много островов, см. слабые места).

**Материалы glTF:** `hull_A`, `hull_B`, `parts_C` (Principled: color, ORM — occlusion/roughness/metallic одной картой, normal, emission),
`glass` (непрозрачное тёмное, roughness 0,05), `decals` (alpha blend).

### Узлы (одинаковы во всех LOD; LOD2 без ниш, створок и `Fittings`)
`Tern` → `Hull` (2 примитива: hull_A, hull_B), `Glass`, `Decals`, `EngineNozzle_L/R`, `DriftDrive`, `GearNose`, `GearMainL/R`,
`GearBay_Nose/MainL/MainR`, `BayDoor_Nose_L/R`, `BayDoor_MainL_In/Out`, `BayDoor_MainR_In/Out`, `SensorTurret`, `Cannon_L/R`,

Инстансы делят один меш (сопла, основные стойки, ниши, пары створок, пушки, пилоны). Оси glTF: +X правый борт, +Y вверх, −Z нос;
опоры шасси на y = −2,6. Шасси выпущено, створки открыты (как в hero-модели).

## Как это сделано (`tools/blender/tern/game/`)
| Файл | Назначение |
|---|---|
| `export_game.py` | точка входа: hero-сборка → low-poly → UV → запекание (кэш) → декали → экспорт трёх glTF |
| `hull.py` | корпус: те же SubD-каркасы `design.py` на уровнях LOD0 = 3 (фюзеляж) / 2 (остальное), LOD1 = 2/1, LOD2 = 1/0–1; UV-острова по рёбрам каркаса (слои `li`/`lj`), развёртка один раз на LOD0, остальные LOD берут UV из него по островам; точные вырезы остекления и ниш шасси (контуры из `ship.py` через `kit.Panelizer`); левый борт — зеркальная копия правого (общие UV) |
| `parts_low.py` | детали: удаление мелких «островов» (болты, заклёпки), planar + collapse decimate до бюджета, ниши — открытые коробки; Smart UV + общая упаковка в атлас C; LOD1/2 — дальнейшая децимация с сохранением UV |
| `bake.py` | runtime-патч материалов: группа `GameBakeMode` переключает `TernSurface` (и прочие материалы) в режимы 1 = итоговый base colour, 2 = ORM (AO-нод 0,6 м); выбросы → чёрный albedo; линзы `sp_lens_glass` вырезаются из источников; все источники склеиваются в один меш (координаты Object сохраняются в атрибуте `lco`) — это ускорило запекание в ~50 раз |
| `decals.py` | атлас декалей из `tools/blender/tern/decals/*.png` и тонкие квады по low-поверхности (+4 мм), данные из `Body.decals` |
| `verify.py` | рендеры hero vs игровая версия с одинаковыми камерами/светом |
| `godot_import_params.py` | VRAM-сжатие + мипмапы для текстур в `.import` (первый headless-импорт делает их lossless без мипмапов) |
| `uvdump.py`, `probe.py` | отладка (UV-раскладки, состав hero-сцены) |

Чужие файлы не менялись: все изменения поведения материалов — патчи нод во время работы скрипта.

## Как пересобрать
```
blender -b --factory-startup -P tools/blender/tern/game/export_game.py -- [--rebake=all|A,B,C|A_color,...] [--samples=16]
python tools/blender/tern/game/godot_import_params.py      # один раз, после первого импорта Godot
<godot> --headless --path . --import
```
Полный прогон с запеканием всех атласов: ~5,5 мин на RTX 3060 (сборка hero ~11 с, low-poly ~30 с, 12 проходов запекания
4096² × 16 сэмплов ~3,5 мин, 12–22 с на проход, экспорт ~1,5 мин). Запечённые PNG кэшируются в `build/tern/game/`
вместе с хэшем UV-раскладки; атлас перезапекается, только если раскладка изменилась. Атлас C перезапекается каждый
прогон (~80 с): упаковка Smart UV в Blender недетерминирована.

## Отличия от hero-рендера и слабые места (честно)
- **Детали (атлас C)** — самое слабое место: после децимации и Smart UV ~10 тыс. мелких островов, плотность в среднем ~190 px/м
  и неравномерна; вблизи (< 2 м) на соплах, дрифт-приводе и стойках видна размытость и шум нормалей, кое-где грани
  острова не допечены (тёмные/плоские пятна на скрытых внутренних поверхностях). Дрифт-привод светится слабее, чем в hero
  (мелкие светящиеся витки ушли при децимации).
- **Плоские фитинги** (вентиляционные решётки, RCS, лючки, ручки, петли, крепёж, VTOL-сопла) теперь только в картах:
  при скользящем взгляде нет глубины/параллакса; решётка у фонаря и ступенька — плоские.
- **Стекло** непрозрачное: интерьера-«ванны» и кресел за фонарём нет, отражения в Godot зависят от окружения.
- **Декали** немного более «потёртые» и зернистые, чем в hero (износ запечён в маску; шум другой).
- В hero есть эффект Bevel-шейдера на всех рёбрах; в игре он запечён в нормали только у корпуса и крупных деталей.
- Поверхности корпуса внутри других тел (фюзеляж под щёками и корнем крыла, крыло внутри гондолы) не удалены —
  тратят треугольники и текстурное место.
- В Godot яркое ядро сопла даёт сильный glow (сила излучения 64,8 как в hero); для полёта стоит управлять `emission_energy` из кода.
- LOD-переключение не настроено (нет `visibility_range`): три файла лежат отдельно.

## Что нужно для интеграции в игру
1. Маркеры и анимируемые части по контракту `tools/blender/ship.py` (двигатели/факел, RCS, шасси, трап, фонарь, огни) —
   сейчас есть только именованные узлы сопел, стоек и створок.
2. Убранное шасси и закрытые створки (полётная конфигурация) — в hero-модели её нет; нужны оси вращения стоек/створок.
3. Коллизии (упрощённые выпуклые формы корпуса, гондол, крыльев) и точка/площадка посадки.
4. LOD-контейнер (`visibility_range` или `LOD`-узлы), материалы двигателя с управляемой яркостью.
